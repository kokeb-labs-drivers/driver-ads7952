Detailed Description

The SPI port of the ADS7952 driver: the CRTP base, the SpiPort concept and the 16-bit frame.

The driver never calls an SDK. It calls hooks on a class you derive from ads7952::SpiInterface<Self>:

Hook Contract
bool EnsureInitialized() noexcept Bring the bus up on the first call; true at once afterwards
bool Transfer(const uint8_t* tx, uint8_t* rx, std::size_t len) noexcept One full-duplex transfer of len = 2 bytes with CS low throughout and high after
void DelayUs(uint32_t us) noexcept Wait at least us microseconds (once, at start-up: the power-up time)

Every frame is one 16-bit word, MSB first, and the chip starts a conversion on each CS falling edge, so CS must go high between two frames and stay low for exactly 16 SCLK cycles: the driver calls Transfer() once per frame, always with 2 bytes and both buffers. What the chip needs from the bus is below as constexpr values (kSpiMode to kContinuousWord, datasheet sections 7.3, 7.9 and 8.1); a port checks its settings against them with static_assert. The SCLK rate and the CS high time set how long the next channel acquires (from the 14th rising edge to the next CS falling edge, section 8.1), so choose the rate for your input network. The port moves raw bytes: it never retries, never interprets the frame and never configures the chip. The optional Log() hook is described in ads7952.hpp.
